# Method Notes

This guide is product documentation, not a systematic-review methods textbook.
It uses established evidence-synthesis concepts so the tutorial feels familiar
to research teams.

## Protocol Before Search

The tutorial asks the team to define the question, eligibility criteria, search
policy, language policy, reviewer policy, AI policy, and full-text policy before
running searches. This keeps screening decisions tied to rules that were
visible before records were reviewed.

## Search Reporting

The walkthrough records provider names, query strings, date limits, result
limits, raw counts, unique counts, and provider failures. Those details are
important because search results are not self-explanatory after the fact.

## Team Screening

The tutorial uses two reviewers because independent review and explicit
adjudication are common safeguards in systematic-review workflows. Nexus
Scholar keeps reviewer decisions, conflicts, final decisions, and audit reasons
visible.

## AI Assistance

AI can help triage or draft rationales when it is explicitly enabled, governed,
and audited. The public tutorial uses human-only screening so the scientific
example does not depend on an LLM response. If AI screening is enabled later,
teams should treat it as assistance, not as the final eligibility authority.

## Evidence Limits

The real example should be interpreted conservatively. Digital health and
coaching interventions may improve some behavioral or process outcomes in some
settings, but the evidence is mixed across outcomes and intervention designs.
The tutorial is therefore written as a workflow demonstration, not as a claim
that digital health interventions are effective for every cardiometabolic
population.
